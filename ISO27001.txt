1. WHOLE-APP ISMS ARCHITECTURE & POSTURE OVERVIEW
--------------------------------------------------------------------------------
- Confidentiality Controls : 
  * Strict Firebase Authentication with Google Sign-in provider (src/lib/auth.ts).
  * Role-Based Access Control (RBAC) enforced via Firebase Auth Custom Claims (superadmin, merchant, agent, supporter) and Firestore security rules (firestore.rules).
  * Tenant and user data isolation: Private messages, user profiles, and inquiry submissions are restricted server-side by UID match or role claims.
  * Secret Management: Zero hardcoded secrets in source or client bundle; Stripe API Secret Key and Webhook Signing Secret are stored in Google Cloud Secret Manager (functions/src/index.ts).
  * Cryptography: End-to-end HTTPS/TLS 1.3 in transit; AES-256 encryption at rest managed natively by Google Cloud Firestore and Secret Manager.

- Integrity Controls       : 
  * Data Contracts & Schemas: Strict JSON/Zod schemas with `additionalProperties: false` across all entities (src/types/contracts.ts, data-contracts.MD).
  * Server-side database enforcement: 952 lines of Cloud Firestore Security Rules validating types, lengths, string patterns, enum ranges, and field immutability (firestore.rules).
  * Financial integrity: Supporter tokens use strict positive integers (Math.round, no float arithmetic; functions/src/tokenRules.ts); token balance credits are gated strictly by Stripe webhook cryptographic signature verification (functions/src/index.ts).
  * Review Integrity: Two-stage moderation pipeline where user reviews remain unapproved (isApproved: false) until reviewed and approved by a superadmin (src/lib/reviews.ts, src/components/ReviewModerationPanel.tsx).

- Availability Controls    : 
  * High-availability serverless architecture distributed across Google Cloud regions.
  * Rate-limiting and error-resilient client caching: Foreign exchange rates from Frankfurter API cached in localStorage for 6 hours with offline fallback (src/lib/fx.ts).
  * Zero local binary storage: Image uploads are processed via client-side canvas 16:9 crop and hosted on ImgBB CDN (src/lib/imgbb.ts), eliminating server disk saturation risks.

- Clauses 4-10 Posture     : 
  * Clause 4 (Context): Scope clearly demarcated between client SPA, cloud functions, and third-party SaaS (Stripe, Google Auth, ImgBB).
  * Clause 5 (Leadership): Security responsibilities assigned via Superadmin roles and developer security mandates.
  * Clause 6 (Planning): Risk assessments conducted for PII leaks, unauthorized balance modification, and malicious payload submission.
  * Clause 7 (Support): Documented contracts in data-contracts.MD and instructions in nextinstructions.txt.
  * Clause 8 (Operation): Secure SDLC, input validation, strict CSP/CORS posture, and automated schema checks.
  * Clause 9 (Performance Evaluation): Firestore and Cloud Functions audit logs in Google Cloud Console.
  * Clause 10 (Improvement): Continuous remediation workflow tracked in nextinstructions.txt.

- Amendment 1:2024 Note    : 
  * Climate & Sustainability Considerations: The application runs exclusively on carbon-neutral Google Cloud Platform serverless infrastructure (Firebase Hosting, Cloud Functions v2, Firestore). Compute resources scale to zero when idle, minimizing unnecessary power consumption.
